# MieGO UX方針書（検討用草案）

状態: **Draft／未確定**。作成日: 2026-10-19。対象: 9路盤MieGOの現行Web UI。

## 1. 目的と原則

- **スマートフォン縦画面を第一対象**とする。碁盤を主役にし、着手に必要な可視領域をできる限り確保する。
- **スマートフォン横画面への最適化は対応不要**。横向き専用レイアウト、横向きを促すUIは設計しない。
- 操作・情報・装飾を増やす前に、既存の表示枠の再利用、状態による切り替え、省略を検討する。
- **無用なカード表示で線を増やさない**。まとまりは余白と文字の大きさで示し、枠線・背景・区切り線は付けない。碁盤の下は碁盤の枠、アゲハマの枠、ボタンの枠が並ぶので、そこにカードの枠を足すと線が重なって見える（例：採点の得点欄は枠なし）。
- 通常の着手・終局提案・パス・投了・採点への同意はそれぞれ異なる行為として扱う。
- AIの推定は確定情報ではない。死石候補は利用者が訂正・確認できるようにする。
- 対局の途中で状態が変わっても、操作位置と情報の意味をできるだけ安定させる。

## 2. 現状から採用する設計

| 対象 | 方針 |
| --- | --- |
| 碁盤 | 縦スマホ画面では大きさを優先。グラデーションを盤面に重ねる |
| 碁盤の見た目 | 「木目／ライト／ダーク」の3種。地合いの色（白〜黒・橙〜紫・緑〜紫・表示しない）は碁盤ごとに調整し、黒側と白側が同じくらい目立つようにする。紫はいつも黒側。盤上に地合いのマークや死石の印は描かない |
| 着手操作 | 「待った（仮置き中は×）┃投了┃パス」を1つにつなぎ、主操作「ここに打つ」を右に離して同じ操作列に維持 |
| 採点操作 | 同じ操作列を「対局を再開／この計算に同意／…」（先へ進む操作を右）へ切り替える |
| 終局提案 | 碁盤下の分析ステータスから必要時だけインライン展開 |
| 終局判定 | KataGoのOwnershipは参考。提案はプレイヤーが明示的に行う |
| 死石 | 自動推定した候補を盤上で修正し、採点確定前に確認する |
| AI再戦 | 設定シートの「AIの設定・再戦」、またはモード選択から開く。終局後は操作列の「もう一局」 |
| 友人招待 | 設定シートの「招待URLを表示」から再表示する |
| 新規対戦シート | 上から「現在の対局に戻る」（強調枠）→ 区切り線 → 開始ボタン（主操作。1台＝「対局を始める」、AI＝「AIと対局を始める」、友人＝「招待リンクを準備する」）→ 対局の種類（1行4つのタブ）→ 盤・ルール・自分の石 → AIの強さ → 詳細設定。カードで囲まない |
| 設定・履歴 | 独立した小さなシート。普段は盤面の場所を占有しない |
| 着手禁止点 | コウ＝丸に斜線、自殺手＝丸に×。同じ色・大きさ・濃さ |
| 待った | 全モードで操作列左端の同じボタン（↺＋「待った」）。仮置き中だけ×（仮置きを戻す）に変わる。1台＝直前の1手、AI＝自分の直前の手まで、URL＝相手が受け入れたら自分の直前の手まで。URLの申し出と返答は終局提案と同じ欄で行う |
| 自分の石 | AI・URLとも「ランダム／● 黒／○ 白」を同じ並びで出す。AIだけ末尾に「観戦」を加える（自分は打たず、COM同士の対局を見る）。初期値はURL＝ランダム、AI＝黒 |
| 観戦（COM同士） | AIが両方の色を一手ずつ間を置いて打つ。操作列は「一時停止（再開）」だけにする。盤を1回タップすると介入になり、COMは止まってその手番の石を仮置きする。ふだんの対局と同じく別の点を打てば仮置きが動き、金の「ここに打つ」で確定するとその色を引き継いで、以後はふつうのAI対局になる。「×」で介入をやめると、少し間を置いてから観戦を続ける。介入のための確認カードやボタンは別に置かない。AI対局中はどの色で始めても、「新規対戦」→「対COM」の「この対局を観戦する」でいつでも観戦に移れる。観戦中は盤の拡大を保つ。黒と白のCOMは強さ・侵入度・補強度を別々に持つ。シート上部の「AIの強さ」は1本のままで、観戦では両方のCOMに効く。黒と白で別々にする設定は「詳細設定」に置き、観戦のときだけ「● 黒のCOM」「○ 白のCOM」の枠を1つずつ出す。枠の中は「強さ／侵入度／補強度」の3行で、それぞれ選択肢ボタンを並べる（説明文や目盛りは付けない）。片方の値を隠す切り替えは置かない。観戦ではヒントの設定を出さない |
| 自由に置く | 新規対戦のルール「自由」。いつも表示し、使えない対COMではグレーアウトする（1台で打つ・対友人で使える）。空いた交点をタップすると選んだ色の石をすぐ置き、石をタップすると取り除く（仮置きなし）。操作列は「待った／● 黒／○ 白」。置く色は各自が選び、共有しない。手番はなく、対友人ではどちらもいつでも両方の色を置ける。同時に置いて食い違ったら招待した側の盤に合わせる。石は取れず、着手禁止点・パス・投了・採点はない。地合いの色は通常どおり表示する。SGFと共有リンクはその局面の置き石（AB/AW、RU[Free]）で書き、着手のない置き石だけのSGFは自由な盤として開く |
| ヘルプ | 説明文は見出し右上の「?」から開くヘルプシートに集約する。各画面には小さな「?」（`.help-button`、`data-help`で話題を指定）を置き、押すとその話題だけを「?」のそばの小さなポップアップで表示する（本文はヘルプシートの項目を複製し、二重に書かない）。ほかの場所をタップするかEscapeで閉じる。設定や操作欄には長い説明文を置かない。先頭の「初心者の方へ」から、ルールと今の局面について好きなAIに聞く質問文をコピーできる（P2Pの部屋URLは含めない） |

## 3. ボタンの規則

### 3.1 種類（4種類のみ）

| 種類 | クラス | 用途 | 例 |
| --- | --- | --- | --- |
| 主操作 | `.primary`（金） | その列で最もよく使い、取り消せる前進操作。1列に1つまで | ここに打つ、この計算に同意、もう一局、採点へ進む（1台・AI） |
| 通常 | `.secondary`（素の `<button>` も同じ見た目） | それ以外のすべて | パス、待った、対局を再開、メニュー内の各項目、設定シートの各操作 |
| 強調枠 | `.accent-outline`（金の枠と文字） | 今の画面から離れる、または説明を得る補助操作 | 最新に戻る／対局に戻る、AIへの質問をコピー、SGFファイルを読み込む |
| 確認待ち | `.danger-armed` | 取り消せない操作が2回目のタップを待っている状態 | 投了？ |

- 色は `:root` の `--btn-*`・`--accent-*`・`--danger-*` だけから取り、ボタン個別の色指定はしない。
- 例外は見出し・シートの透明なアイコンボタン（`.icon-button`）、手数表示のチップ（`.move-history-toggle`）、局所ヘルプの「?」（`.help-button`）の3つだけ。「?」は行の高さを変えないよう小さく描き、`::after`でタップ領域を広げる。
- 相手との交渉（URL対戦の終局提案・待ったへの返答）では、どちらの選択肢も主操作にしない。
- ポップオーバーの中では主操作を使わない。

### 3.2 寸法

- 盤下の操作列・採点列・再生列は同じ高さ `--action-h`（55px、幅700px以下は54px）。状態が変わっても行の高さは変わらない。
- それ以外のボタンは `--control-h`（44px）以上。
- 角丸は `--radius`（13px）。ポップオーバー内の小さなボタンだけ `--radius-sm`（10px）。

### 3.3 文言とアイコン

- 同じ操作は、どこでも同じ名前と同じアイコンにする。
  - 仮置きを戻す：×アイコン（aria-label「仮置きを戻す」）。対局中でも棋譜再生中でも同じ。
  - 保存した棋譜を開く：「保存した棋譜」（シートの題名と同じ）。
- ラベルは動詞で終える（例：「SGFを保存」）。
- シートの閉じる、前後移動、メニューはSVGアイコンで描き、文字の記号（× ‹ › ≪ ≫ •••）は使わない。

### 3.4 確認の手順

| 操作の性質 | 確認 | 例 |
| --- | --- | --- |
| 取り消せる | 1タップ | パス（待ったで戻せる）、「新規対戦」→「対局を始める」（直前の対局は保存した棋譜に残る） |
| 取り消せない、盤下の操作列にある | その場で2回押す | 投了 |
| 取り消せない、モード選択やシートから盤面を離れる | その場で2回押す。加えて直下に何が起きるかを一文で示す | 友人との対局から離れる |

- 2回押しの1回目では、必ずボタンそのものを変える。`.danger-armed` の色にし、ラベルの末尾を「？」にする（例：投了→投了？、対局を始める→対局を始める？）。色だけ・周囲の文だけの変化にはしない。

- ブラウザの確認ダイアログ（`confirm()`・`alert()`）は使わない。見た目と操作がアプリの他の部分と揃わず、読まずにOKを押す癖もつきやすいため。
- 確認待ちは、そのボタン以外を押すかシートを閉じると解除する。

### 3.5 メッセージの書き方

エラーや注意の文言は、状態の説明ではなく**利用者が次にすること**を先に書く。

- 「次にすること。理由。」の順にする。理由は行動に納得するのに要る分だけ短く添え、明らかなら省く。
  - よい例：「別の交点を選んでください。コウで打てません。」「今の招待URLをそのまま使ってください。招待は作り直せませんでした。」
  - 避ける例：「その交点は禁止です。コウだからです。」「局面が一致しません」
- その場でできない操作は、文言で断らずにボタンを無効化（グレーアウト）する。押せる操作には失敗の説明を出さなくて済むようにする。
- 利用者の言葉で書く。システムの用語（同期、接続、データ、不正、初期化、サーバーの応答など）は使わない。「本人確認」のように仕組みと違う言い方もしない（Turnstileは「ロボットでないことの確認」）。
- 壊れた棋譜・SGF・URLは、壊れ方を区別せず一つに扱い、その場面でできること（別のファイルを選ぶ、URLを送り直してもらう等）を出す。対応していない形式は、選ぶべきファイルの条件を書く（「512KB以下のSGFファイルを選んでください」）。
- 画面に出すのは `public/texts.mjs` の文言だけ。ブラウザ・サーバー・プログラム内部のエラー文はそのまま見せず、場面ごとの文言に置き換える（`UserError` と `messageFor`）。開発者向けのログや例外は英語でコードの横に書く。
- 進行中の表示（「〜中…」「相手を待っています」）は、することが「待つ」だけなので状態のままでよい。
- 表示枠に収める（幅360pxで確認）。
  - 手番の横の接続状態：短い状態だけ（「つながりません」）。することはヘッダー下のお知らせに出す。
  - 禁止手の表示：2行以内（盤下の欄の高さは変えない）。
  - お知らせ：2行以内。

### 3.6 関連するボタンの融合

関連するひとまとまりのボタンは、区切り線でつないだ1つの部品（`.fused`）にする。無関係なボタンとは今までどおり隙間をあける。

```
[1][2][3][A]  →  [1┃2┃3]  [A]
```

- **融合するもの**
  - 1つの問いへの選択肢（ラジオ）：新規対戦の対局の種類・盤・ルール・自分の石、設定の濃さ（V字／U字）。
  - 同じ場面で並ぶ同格の操作：操作列の「待った┃投了┃パス」、採点列の「対局を再開┃死石判定に戻る」、再生列の「‹┃n手目┃›」。
  - 縦に並ぶ同じ種類の操作：共有シートの棋譜の3つ、ヘルプ「初心者の方へ」の質問コピー2つ（`.fused-column`）。
- **融合しないもの**
  - 主操作（`.primary`）。常に独立させ、隣と隙間をあける（ここに打つ、この計算に同意、もう一局、開始ボタン）。
  - 強調枠（`.accent-outline`）とメニュー（•••）。今の画面から離れる操作なので、まとまりの外に置く（再生列の「戻る」）。
  - 見本の絵で選ぶカード（碁盤の見た目、地合いの配色、共有画像の種類）。絵どうしを比べやすいよう1枚ずつ枠で囲む。
  - 同時に1つしか出ないボタン（採点の「スキップ／決着手順を再生／AIに続きを打たせる」）。
- **描き方**
  - 外枠は1本、角丸はまとまりの両端だけ。区切り線は1px（`--btn-edge`、シートの選択肢は `#505766`）。
  - 選んでいる選択肢は、今までどおり金の文字と背景に、内側の金の線を加える。
  - 無効なボタンはボタン全体ではなく文字だけを薄くし、区切り線の濃さを揃える。
  - まとまりの一部が非表示になっても線は余らない。全部が非表示ならまとまりごと消える。
  - 高さとタップ領域は §3.2 のまま（44px以上、盤下の列は `--action-h`）。融合で隙間がなくなる分、320px幅で隣のボタンが広くなる。
- 1つのまとまりは5つまで（iPhoneの目安）。それを超えるなら選び方そのものを見直す。
- 取り消せない操作（投了）がまとまりに入っても、§3.4 の2回押しで誤タップを防ぐ。

## 4. 状態別の画面規則

| 状態 | 目立たせるもの | 抑える／非表示にするもの |
| --- | --- | --- |
| 自分の手番 | 手番表示、碁盤、着手操作、合法・禁止点 | AI・通信の詳しい説明 |
| 仮置き中 | 仮置き石、確定・戻す操作 | 不要な操作の有効化 |
| AI思考中 | 計算中ステータス、盤面 | 人間の着手確定操作 |
| 観戦中 | 盤面とグラデーション、手番、一時停止、盤タップでの介入（×・ここに打つ） | 着手・待った・パス・投了 |
| 相手待ち／切断 | 接続状況、再接続の見通し | 成立しない対局操作 |
| 終局を提案・受信 | 終局ステータス、必要な同意・続行操作 | ポップアップ・独立した固定バー |
| 死石解析中 | 解析中表示、盤上の死石修正、対局再開 | **採点確定ボタンを有効化しない** |
| 採点確認中 | 石の仮指定、目数、採点の再開／同意 | 通常の着手操作 |
| 対局終了 | 勝敗・目数（投了では投了勝敗）、棋譜 | 無効な着手操作 |

## 5. 未決の検討事項

1. **最小対応サイズ**: 縦画面320×568pxを必須とするか。文字・ボタン・碁盤の最小寸法を確認する。
2. **スクロール規則**: 碁盤が大きい端末で、採点詳細と固定操作列が重ならない位置を決める。
3. **AI不在時の手動採点**: KataGoがいつまでも読み込めない場合、どの既存操作で明示的に手動採点へ進むか。
4. **ネット切断・再接続**: 状態、再試行可否、招待URLの利用可能性をどこまで表示するか。
5. **履歴と再戦の区別**: 既存対局の再開、新規対局、設定変更を混同させない文言・確認手順。
6. **アクセシビリティ**: タップ領域44px目安、文字サイズ、フォーカス移動、Canvasの代替操作。
7. **初回学習**: 終局の提案とパスの違い、コウ・自殺手、死石の修正はヘルプシートで説明する。初回起動時に自動で案内するかは未決。
8. **通信競合時の整合性**: 双方が同時に死石修正した場合の最終確認と、盤面が食い違ったときの回復方法。

## 6. レビュー時の確認環境（暫定）

- 320×568、375×667、390×844、430×932相当のスマートフォン**縦画面**を優先。
- 768×1024のタブレット、一般的なデスクトップは二次対応。
- **スマートフォン横画面は合否の対象外**とする。
- 3モード（1台・友人・対AI。対AIは観戦を含む）× 主要状態（通常、仮置き、待機、終局提案、採点、終了、失敗）をテスト。
- 機能テストだけでなく、実機の画面外への押し出し、同意・戻るの誤操作、通信復帰時の状態を確認する。

この草案は、未決の項目について関係者が合意した後に正式版とする。
