# MieGO: AIの性格（設計と実装の記録）

この文書は設計案と実装の記録です。現在は、強さ（5段階）と性格の3軸（戦い方・序盤・相手の手に）による方針logitの補正を実装済みで、7つのキャラとカスタムから選びます（下の「2026-10-20・キャラと軸の整理」）。候補手ごとのニューラル再評価とMCTSは未実装です（「最強」の1手読み・2手読みを除く）。

## 基本方針

「強さ」「乱れ・多様性」「棋風」を混同しない。温度（以前の標準/ばらつき大の切り替えは廃止）は性格ではない。生死や地合いの確実さをOwnershipだけで判定してはいけない。

### 推奨する性格プリセット

| 性格 | 好む手 | 控える手 |
| --- | --- | --- |
| **侵入型** | 相手の確保が見込まれる地域の中へ入り、根拠を作る | 相手の模様を外側から消すだけの穏当な手 |
| **削減型** | 相手の勢力圏の境界から模様を縮小し、撤退できる形を確保 | 生存困難な深い侵入 |
| **堅実型** | 自陣の弱い石の補強、確実に地になる場所 | 複雑な打ち込み・切断 |
| **戦闘型** | 相手の弱い連への攻め、切断、取り・シチョウなど | 戦闘を避けるだけの固め |
| **模様型** | 厚みと勢力を作る広い着手、外勢の利用 | 狭い地をすぐに確定させる手 |
| **地取り型** | 隅・辺の確保、地として読みやすい展開 | 勢力重視の広がり |

**MVP候補:** 侵入型・削減型・堅実型・標準の4種。性格に「強弱」は混ぜず、同じ棋力・モデルで選好だけを変える。

### 詳細パラメータ

UIは最初プリセットを選択するだけにし、後で「侵入度」「補強度」を別スライダーとして公開する。

- **侵入度**: 相手が所有している可能性が高い地点とその周囲への打ち込みを好む。ただし生きられない敵地への乱入を無条件に増やさない。
- **削減度**: 相手のOwnershipが中程度の境界を狙って相手の模様を縮小する。深い敵地の候補とは分けて扱う。
- **補強度**: 自石連の呼吸点・逃げ道・生存可能性を優先する。既に確保済みの自分の眼を埋めるのとは違う。
- **戦闘度**: 相手の弱い石を分断、攻撃、捕獲する手を好む。単純な隣接石数だけで判断しない。
- **模様度**: 周辺への影響・将来の勢力を作る候補を好む。
- **ばらつき**: 方針分布のサンプリング温度。性格とは独立。
- **強さ**: 探索量や上位手との価値差に対する許容範囲。性格とは独立（2026-10-19に5段階で実装、下記）。

## 段階的な実装

### 第1段階: KataGo policyを再順位付けする（軽量・近似）

KataGoの候補手のlogitsを基礎とし、AIの手番で取得したOwnershipの値、石の呼吸点、候補の局所的な位置関係を使ってスコアを加算する。

```
score(m, persona) =
  log_policy_KataGo(m)
  + w_invade * invasion_feature(m)
  + w_reduce * reduction_feature(m)
  + w_secure * group_safety_feature(m)
  + w_fight * tactical_pressure_feature(m)
  + w_framework * outward_influence_feature(m)
  - safety_penalty(m)
```

黒を+1、白を-1とするKataGo Ownershipの符号は、AI側から見た正負に統一する。候補に相手Ownershipの大きい地点を含むだけでは、侵入の成功を意味しない。着手候補は必ずMieGO側の合法手エンジンで検証し、低方針確率の極端な手は除く。

**制約:** 盤面のOwnership1回だけでは、侵入後に本当に活きられるか、補強が価値を持つかは分からない。「性格の表面上の傾向」を作る段階と定義する。

### 第2段階: 上位候補を再評価する（推奨）

合法な方針上位8〜12手に各1手を仮着手した局面を作り、KataGoのOwnership・目数差を再推論する。候補によって変化した領域を比較する。

- **侵入型**: 元々敵が優勢な領域で、打った後に相手Ownershipを減らす候補を優先する。
- **削減型**: 相手の模様周辺でOwneshipを変えつつ、自石の弱さを増やしにくい候補を優先する。
- **堅実型**: 自石グループの危険度改善を重視し、自己の地中に無意味な着手をしない。
- **戦闘型**: 相手の弱い石の自由度や捕獲可能性を調べ、局所戦で損をしない候補を優先する。

局面評価は **KataGoの推論を別Workerで一度に複数局面バッチ処理**するか、UI描画の邪魔にならない範囲で小分けにする。ユーザーの仮置きに関する評価とAI着手探索が競合する際はAI着手の処理を優先。スマホでは候補数・探索時間の上限を厳しく設ける。

### 第3段階: MCTS探索と性格重み付け（将来）

棋力や生存率を保ちながら好みの着手を選ぶには探索が必要。KataGoの MCTS 候補や ownership を利用し、候補ごとの期待損失が一定以内のものだけに性格のボーナスを加える。ネットのpolicy temperatureを上げるだけでは「侵入型」や「堅実型」にならない。

## 実装上の必須条件

- **KataGoが利用できない環境では対AI戦を開始しない。** 対局中に利用不可となっても簡易AIへ切り替えない（PR #2）。
- 9・13・19路、中国式（コミ7.5）と日本式（コミ6.5、KataGoの`japanese`ルール）を対象とする。五目並べのCOMはKataGoを使わない別処理。
- 棋風の変化を「強さを弱くしただけ」にしないため、対局例で侵入頻度・弱い連への手入れ率・優勢な手からの目数差損失・着手時間を別々に測定する。
- 堅実型の自己眼埋め、侵入型の無謀な自殺手、戦闘型の無意味なアタリを回帰テストで防ぐ。
- モデルの小型テストネットワークでは棋風の再現性・強さを保証しない。棋風パラメータは局面と棋力に応じて調整が必要。

## 実装進捗（2026-10-19）

（2026-10-20に廃止し「戦い方」に統合。以下は当時の記録）PR #2 の設定パネルへ**侵入度**と**補強度**を0〜100で独立追加。50は中立。KataGoの候補手から合法手をフィルターしたうえで、現在のOwnership・弱い自石の呼吸点・境界の形のヒューリスティックを使って方針logitsを補正する方式です。深い侵入後に生きられるかなどは判断できず、性格調整の試作です。候補手ごとのニューラル再評価およびMCTSは将来課題です。

### 棋力の設定案

**棋風・ばらつき・棋力は独立の3軸。** 優先順位は以下のとおり。

1. **短期（既存ネットワーク）:** KataGoの方針上位候補をそれぞれ1手仮置きしてネットワークでスコア評価し、最善手から許す目数差・勝率損失幅を棋力段階で変える。ただし実際の段級位ではない。処理コストと対局統計が必要。
2. **中期:** KataGoのMCTSをブラウザに実装し、訪問回数・時間を棋力に応じて調節。単純に訪問回数だけ変更しても段級位が定まるわけではないため、同モデル・同持ち時間の対局実測で校正する。
3. **長期:** KataGoのHuman SLモデルの `rank_20k`〜`rank_9d`プロファイルで、人間の階級に近い方針を出す。これは現在の3.8MBテスト用モデルとは異なる**追加モデルの導入が必要**。小型ネットと混ぜてHuman SLが動くわけではない。段級位の再現性は対局統計で検証する。

この3種を混ぜずに「弱いAI」「強いAI」などの表示を選ぶ場合は、対局データで検証した強さの範囲を明記する。0〜100の侵入度と補強度は棋力指定ではない。

## 実装進捗（2026-10-19・初心者向けの強さ）

棋風（侵入度・補強度）とは独立に、**AIの強さ**を4段階で追加した（`public/ai-strength.mjs`）。のちに大きいネットで打つ「最強」を加えて5段階になった（READMEの「導入したKataGo」参照）。

- 入門／やさしい／ふつう：KaTrainの`RankStrategy`（MIT）の式で、合法手数と内部の`kyu`値（30/20/12）から抽選数Nを求め、無作為に選んだN手のうち方針logit＋棋風補正が最大の手を打つ。方針の最上位手の確率が閾値を超える場合、上位2手の合計が閾値を超える場合、パスが方針上位5位以内の場合は最上位手を選ぶ（KaTrainの`should_play_top_move`と同じ考え方）。
- つよい：従来どおり上位候補の温度付きサンプリング。
- 内部の`kyu`値は**表示しない**。KaTrainは19路盤・フルサイズネットで校正しており、9路盤小型ネットでの段級位対応は未検証。下の「棋力の設定案」の対局実測による校正は引き続き必要。
- 弱い段階は自分の眼を埋める手を抽選から除外する（ただし方針最上位の場合は除外しない）。

**実測（2026-10-19、小型テストモデル・Node.js CPU推論、隣接段階同士で各20局・先後交互・コミ7.5・終局は双方パスまたは145手、死石は`suggestDeadStones`で推定）：**

| 対戦 | 上位段階の勝数 |
| --- | --- |
| つよい vs ふつう | 19/20 |
| ふつう vs やさしい | 15/20 |
| やさしい vs 入門 | 18/20 |

段階の順序は保たれたが、AI同士の対局であり、人間に対する勝率や段級位を示すものではない。局数が少なく、「ふつう」と「やさしい」の差は小さい。

既知の限界：弱さは「方針から外れた手」によって作られるため、人間の同棋力者のミスの傾向（例：死活の見落とし）とは一致しない。より人間らしい弱さにはHuman SLモデル（長期案）や置き石（下記）が候補になる。

### 置き石（ハンディキャップ）— 2026-10-19 実装

囲碁の指導では、強さの差を相手の手加減ではなく**置き石**で埋めるのが伝統的な方法で、9路盤の初心者指導では4〜6子程度から始める例が多い。置き石は相手（AI）が全力で打っても勝負になるため、手加減による不自然さがない利点がある。実装：対局状態に`handicap`（9路は2〜5、13路・19路は2〜9）と`komi`（置き碁は0、持碁あり）を持たせ、置き石は星に固定配置する（9路盤の星は5点のため上限5子）。採点は中国式で白にコミ＋置き石数を加算する（日本式は加算しない）。KataGoへの入力コミも同じ値（KataGoの`chinese`ルールは`whiteHandicapBonus=N`で、NN入力の`selfKomi`はこの補正込み）。棋譜の再生・待った・SGF（`HA`/`AB`）は置き石局面から再構築する。当初は友人とのP2P対局は互先のみだったが、現在は友人対局でも置き石を選べる。

## 実装進捗（2026-10-20・キャラと軸の整理）

方針は `/mnt/project-files/research/AIの性格の方向性.md`（プロジェクトの共有フォルダ）。強さはキャラに含める（Chess.com型）。

### 軸（`public/ai-personality.mjs` の `STYLE_AXES`）

どれも0〜100の3段階で、50は中立。方針logitに最大±3を足す。

| 軸 | 0 | 100 | 測るもの（`personalityFeatures`） |
| --- | --- | --- | --- |
| 戦い方 `stance` | 守る | 攻め込む | 攻め（`attack`）＋ 侵入（`invasion`、相手の勢力圏の中か）− 補強（`reinforcement`） |
| 序盤 `height` | 地を取る | 勢力を作る | 2〜3線は−1、4線以上は+1、1線は0。盤の空きが80%以上で全量、40%以下でなくなる |
| 相手の手に `tenuki` | 応じる | 手を抜く | 直前の相手の手からのチェビシェフ距離。1は−1、3は0、5以上は+1。初手とパスの直後は0 |

- 画面の名前は、読んだだけで意味が取れるよう「攻守・高さ・応じ方」から「戦い方・序盤・相手の手に」に変えた。以下の文と表の攻守・高さ・応じ方は、それぞれこの3つのこと。
- `attack`：取る手・アタリにする手は1、呼吸点2に減らす手は0.3、相手の別々の石の間に打つ（切る）手は0.6。打った石がアタリになる手は0。
- 攻め度と補強度は別々の軸として試したが、どちらも中立の手との差が小さかった（下の表の初版）。キャラでも石橋（補強・攻めない）と喧嘩屋（攻め・補強しない）が逆向きに使っていたので、「攻守」1軸にまとめた。古い保存の補強度は「攻守＝100−補強度」として読む（補強 重視＝守る）。
- 侵入度も一度は別の軸だったが、「攻める」の喧嘩屋は侵入も+0.03〜0.05増え、2つは同じ向きに動いていた。カスタムの行を減らし、効きの小さい攻守を強めるため、侵入も攻守に入れた。古い保存は、攻守（または100−補強度）と侵入度の平均を攻守として読む。囲碁の棋風の分析では「どこに打つか」と「攻め守りの積極性」を別の要素として扱うこともあり、「地に入るが攻めない」荒らし方はこの版では作れない。
- 弱い段階（`ai-strength.mjs`）は、抽選したN手のうち方針logitが最良から3以内（`STYLE_SLACK`）の手の中で、補正後の値が最大の手を打つ。性格が抽選の中のずっと悪い手を選ばないための歯止めで、中立の性格では打つ手は変わらない。

### 画面（新規対戦シート）

「AIの強さ」タブを「COMのキャラ」タブに置き換えた。8択（7キャラとカスタム）の各行に強さと1文の説明を出し、選択肢の下に選んだCOMの強さと好みを1行で出す。カスタムを選ぶと、そのとき選んでいたキャラの値から始まり、選択肢のすぐ下に強さと3軸の行が出る。観戦では黒と白のCOMの枠にキャラのプルダウンを置き、カスタムのときだけ同じ行を出す。初期値はひよこ。保存した対局と設定には `aiCom`（キャラと全部の値）を書き、保存した対局には古い版のために `aiStrength`・`invasion`・`reinforcement`（＝100−攻守）も書く。

### 実測（2026-10-20）

小型テストモデル・Node.js CPU推論、先後交互・コミ7.5・終局は双方パスまたは145手、勝敗は最終局面のOwnership合計で判定。相手は同じ強さで全軸ふつうのCOM。「変えた手」は、同じ局面・同じ乱数で中立の性格なら選んだ手と違った手の割合。「軸の差」は、選んだ手とその中立の手との特徴量の差の平均。

| 版 | キャラ | 勝数 | 変えた手 | 軸の差 |
| --- | --- | --- | --- | --- |
| 初版（5軸・歯止めなし） | 石橋 | 7/20 | 22% | 補強 +0.04、侵入 −0.06、攻め −0.09 |
| | 荒らし屋 | 9/20 | 25% | 侵入 +0.07、高さ −0.15 |
| | 喧嘩屋 | 6/30 | 28〜34% | 応じ方 −0.33、攻め +0.05 |
| | 大場好き | 3/20・8/30 | 34〜45% | 応じ方 +0.41、高さ +0.21 |
| 現行（4軸・歯止めあり） | 石橋 | 9/20 | 21% | 侵入 −0.07、攻め −0.07、補強 +0.03 |
| | 荒らし屋 | 8/20 | 20% | 侵入 +0.09、高さ −0.11 |
| | 喧嘩屋 | 12/20 | 24% | 応じ方 −0.20（距離 −0.5路）、攻め +0.04 |
| | 大場好き | 7/20 | 28% | 応じ方 +0.26（距離 +0.7路）、高さ +0.10 |
| 3軸（侵入を攻守に入れ、攻めと侵入は半分ずつ） | 石橋 | 11/20 | 16% | 攻め −0.07、侵入 −0.04、補強 +0.03 |
| | 荒らし屋 | 11/20 | 17% | 高さ −0.08、侵入 +0.04、攻め +0.02 |
| | 喧嘩屋 | 7/20 | 29% | 応じ方 −0.27、侵入 +0.05、攻め +0.02 |

現行版で打った手の割合：荒らし屋は序盤の2〜3線が85%（相手は62%）、侵入（侵入度0.5以上）23%（同9%）。喧嘩屋は直前の手から2路以内が60%（同47%）、大場好きは31%（同45%）。対になるキャラ同士は各10局で、荒らし屋6勝・石橋4勝、喧嘩屋3勝・大場好き7勝。

分かったこと：
- 3軸版で、攻めと侵入をそのまま足した重みでは石橋5/20・喧嘩屋6/20と同じ強さの中立に負け越したため、2つを半分ずつにした（上の表の3軸の行）。喧嘩屋の勝数はこれまでの測定で20局あたり2〜12勝と揺れており、この版の差は局数の少なさの範囲と見ている。
- 応じ方・高さ・侵入度ははっきり効く。攻守は補強も攻めも差が小さく、KataGoがもともと好む手と重なりやすい。
- 歯止めを入れる前は、「ふつう」の強さに性格を付けると同じ強さの中立に勝ちにくかった（喧嘩屋 6/30、大場好き 11/50）。歯止めで性格の効きは3〜4割減ったが、勝数は中立に近づいた。大場好きはまだ少し弱い。
- 局数が少なく、AI同士の結果で人間に対する強さは示さない。
