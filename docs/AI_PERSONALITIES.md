# MieGO: AIの性格（将来実装の設計）

この仕様は**設計案**です。PR #2 の対AI戦には、現時点でKataGo小型ネットワークの方針から着手を選ぶ仕組みのみを実装します。**性格別の着手重み付けは未実装**です。

## 基本方針

「強さ」「乱れ・多様性」「棋風」を混同しない。既存の標準/ばらつき大の温度設定は性格ではない。生死や地合いの確実さをOwnershipだけで判定してはいけない。

### 推奨する性格プリセット

| 性格 | 好む手 | 控える手 |
| --- | --- | --- |
| **侵入型** | 相手の確保が見込まれる地域の中へ入り、根拠を作る | 相手の模様を外側から消すだけの穏当な手 |
| **削減型** | 相手の勢力圏の境界から模様を縮小し、撤退できる形を確保 | 生存困難な深い侵入 |
| **堅実型** | 自陣の弱い石の補強、確実に地になる場所 | 複雑な打ち込み・切断 |
| **戦闘型** | 相手の弱い連への攻め、切断、取り・シチョウなど | 戦闘を避けるだけの固め |
| **模様型** | 厚みと勢力を作る広い着手、外勢の利用 | 狭い地をすぐに確定させる手 |
| **地取り型** | 隅・辺の確保、地として読みやすい展開 | 勢力重視の広がり |

**MVP候補:** 侵入型・削減型・堅実型・標準の4種。性格に「強弱」は混ぜず、同じ棋力・モデルで選好だけを変える。

### 詳細パラメータ

UIは最初プリセットを選択するだけにし、後で「侵入度」「補強度」を別スライダーとして公開する。

- **侵入度**: 相手が所有している可能性が高い地点とその周囲への打ち込みを好む。ただし生きられない敵地への乱入を無条件に増やさない。
- **削減度**: 相手のOwnershipが中程度の境界を狙って相手の模様を縮小する。深い敵地の候補とは分けて扱う。
- **補強度**: 自石連の呼吸点・逃げ道・生存可能性を優先する。既に確保済みの自分の眼を埋めるのとは違う。
- **戦闘度**: 相手の弱い石を分断、攻撃、捕獲する手を好む。単純な隣接石数だけで判断しない。
- **模様度**: 周辺への影響・将来の勢力を作る候補を好む。
- **ばらつき**: 方針分布のサンプリング温度。性格とは独立。
- **強さ**: 探索量や上位手との価値差に対する許容範囲。性格とは独立し、現段階では実装対象外。

## 段階的な実装

### 第1段階: KataGo policyを再順位付けする（軽量・近似）

KataGoの候補手のlogitsを基礎とし、AIの手番で取得したOwnershipの値、石の呼吸点、候補の局所的な位置関係を使ってスコアを加算する。

```
score(m, persona) =
  log_policy_KataGo(m)
  + w_invade * invasion_feature(m)
  + w_reduce * reduction_feature(m)
  + w_secure * group_safety_feature(m)
  + w_fight * tactical_pressure_feature(m)
  + w_framework * outward_influence_feature(m)
  - safety_penalty(m)
```

黒を+1、白を-1とするKataGo Ownershipの符号は、AI側から見た正負に統一する。候補に相手Ownershipの大きい地点を含むだけでは、侵入の成功を意味しない。着手候補は必ずMieGO側の合法手エンジンで検証し、低方針確率の極端な手は除く。

**制約:** 盤面のOwnership1回だけでは、侵入後に本当に活きられるか、補強が価値を持つかは分からない。「性格の表面上の傾向」を作る段階と定義する。

### 第2段階: 上位候補を再評価する（推奨）

合法な方針上位8〜12手に各1手を仮着手した局面を作り、KataGoのOwnership・目数差を再推論する。候補によって変化した領域を比較する。

- **侵入型**: 元々敵が優勢な領域で、打った後に相手Ownershipを減らす候補を優先する。
- **削減型**: 相手の模様周辺でOwneshipを変えつつ、自石の弱さを増やしにくい候補を優先する。
- **堅実型**: 自石グループの危険度改善を重視し、自己の地中に無意味な着手をしない。
- **戦闘型**: 相手の弱い石の自由度や捕獲可能性を調べ、局所戦で損をしない候補を優先する。

局面評価は **KataGoの推論を別Workerで一度に複数局面バッチ処理**するか、UI描画の邪魔にならない範囲で小分けにする。ユーザーの仮置きに関する評価とAI着手探索が競合する際はAI着手の処理を優先。スマホでは候補数・探索時間の上限を厳しく設ける。

### 第3段階: MCTS探索と性格重み付け（将来）

棋力や生存率を保ちながら好みの着手を選ぶには探索が必要。KataGoの MCTS 候補や ownership を利用し、候補ごとの期待損失が一定以内のものだけに性格のボーナスを加える。ネットのpolicy temperatureを上げるだけでは「侵入型」や「堅実型」にならない。

## 実装上の必須条件

- **KataGoが利用できない環境では対AI戦を開始しない。** 対局中に利用不可となっても簡易AIへ切り替えない（PR #2）。
- 9路盤・中国式・コミ7.5のみを当面の対象とする。
- 棋風の変化を「強さを弱くしただけ」にしないため、対局例で侵入頻度・弱い連への手入れ率・優勢な手からの目数差損失・着手時間を別々に測定する。
- 堅実型の自己眼埋め、侵入型の無謀な自殺手、戦闘型の無意味なアタリを回帰テストで防ぐ。
- モデルの小型テストネットワークでは棋風の再現性・強さを保証しない。棋風パラメータは局面と棋力に応じて調整が必要。

## 実装進捗（2026-10-19）

PR #2 の設定パネルへ**侵入度**と**補強度**を0〜100で独立追加。50は中立。KataGoの候補手から合法手をフィルターしたうえで、現在のOwnership・弱い自石の呼吸点・境界の形のヒューリスティックを使って方針logitsを補正する方式です。深い侵入後に生きられるかなどは判断できず、性格調整の試作です。候補手ごとのニューラル再評価およびMCTSは将来課題です。

### 棋力の設定案

**棋風・ばらつき・棋力は独立の3軸。** 優先順位は以下のとおり。

1. **短期（既存ネットワーク）:** KataGoの方針上位候補をそれぞれ1手仮置きしてネットワークでスコア評価し、最善手から許す目数差・勝率損失幅を棋力段階で変える。ただし実際の段級位ではない。処理コストと対局統計が必要。
2. **中期:** KataGoのMCTSをブラウザに実装し、訪問回数・時間を棋力に応じて調節。単純に訪問回数だけ変更しても段級位が定まるわけではないため、同モデル・同持ち時間の対局実測で校正する。
3. **長期:** KataGoのHuman SLモデルの `rank_20k`〜`rank_9d`プロファイルで、人間の階級に近い方針を出す。これは現在の3.8MBテスト用モデルとは異なる**追加モデルの導入が必要**。小型ネットと混ぜてHuman SLが動くわけではない。段級位の再現性は対局統計で検証する。

この3種を混ぜずに「弱いAI」「強いAI」などの表示を選ぶ場合は、対局データで検証した強さの範囲を明記する。0〜100の侵入度と補強度は棋力指定ではない。

## 実装進捗（2026-10-19・初心者向けの強さ）

棋風（侵入度・補強度）とは独立に、**AIの強さ**を4段階で追加した（`public/ai-strength.mjs`）。

- はじめて／やさしい／ふつう：KaTrainの`RankStrategy`（MIT）の式で、合法手数と内部の`kyu`値（30/20/12）から抽選数Nを求め、無作為に選んだN手のうち方針logit＋棋風補正が最大の手を打つ。方針の最上位手の確率が閾値を超える場合、上位2手の合計が閾値を超える場合、パスが方針上位5位以内の場合は最上位手を選ぶ（KaTrainの`should_play_top_move`と同じ考え方）。
- つよい：従来どおり上位候補の温度付きサンプリング。
- 内部の`kyu`値は**表示しない**。KaTrainは19路盤・フルサイズネットで校正しており、9路盤小型ネットでの段級位対応は未検証。下の「棋力の設定案」の対局実測による校正は引き続き必要。
- 弱い段階は自分の眼を埋める手を抽選から除外する（ただし方針最上位の場合は除外しない）。

既知の限界：弱さは「方針から外れた手」によって作られるため、人間の同棋力者のミスの傾向（例：死活の見落とし）とは一致しない。より人間らしい弱さにはHuman SLモデル（長期案）や置き石（下記）が候補になる。

### 未実装の代替案：置き石（ハンディキャップ）

囲碁の指導では、強さの差を相手の手加減ではなく**置き石**で埋めるのが伝統的な方法で、9路盤の初心者指導では4〜6子程度から始める例が多い。置き石は相手（AI）が全力で打っても勝負になるため、手加減による不自然さがない利点がある。一方でMieGOでは棋譜・SGF・再生・P2P・採点（中国式の置き石分の補正）・KataGo入力が「空盤から黒先」を前提としているため、別PRでの対応とする。
