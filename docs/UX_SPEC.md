# MieGO UX仕様

状態: **Draft／未確定**。作成日: 2026-10-19。対象: MieGO（9・13・19路盤）の現行Web UI。

この文書は**何がどこにあるか**（配置、値、用語）を書く。なぜそうするか（原則と、決めたことの理由）は [`UX_PRINCIPLES.md`](UX_PRINCIPLES.md)（以下「原則」）に書く。

## 1. 原則

原則 §1 を参照。節の番号（§2〜§8）はコードのコメントから参照されているので変えない。

## 2. 画面ごとの配置

### 2.1 縦の並び

- 全モード・全状態で上から「ヘッダー／碁盤／地合いの色のバー（両端は白と黒の小さな石、下にルールとコミ）／◁ ステータス ▷／終局判定／操作列」。
- ステータスと終局判定（採点中は得点欄）は操作列のすぐ上にまとめて置く。
- パネルやカードで囲まず、余白だけで分ける。余った高さはバーとパネルの間に回す。
- 碁盤の上には何も置かない。
- 状態が変わっても順序は入れ替えず、出す・隠すだけにする。

### 2.2 ステータス行

- 中央に手番（さかのぼり中は「28手目を表示中」、観戦中などの状態もここ）、その下に小さく手数と対局の種類・接続状態。
- 1行に収め、長いときは末尾を省く（行の高さを変えない）。
- 左右の◁▷は枠のないアイコンボタンで、1手戻る・1手進む。対局中は最新局面なので▷はいつも無効（グレー）で、◁でさかのぼりに入る。

### 2.3 碁盤

- 縦スマホ画面では大きさを優先。グラデーションを盤面に重ねる。

### 2.4 碁盤の見た目

- 「木目／ライト／ダーク／カスタム」の4種。
- 地合いの色（白〜黒・緑〜紫・カスタム・表示しない）は碁盤ごとに調整し、黒側と白側が同じくらい目立つようにする。紫はいつも黒側。
- 盤上に地合いのマークや死石の印は描かない。

### 2.5 着手操作

- 「待った（仮置き中は×）┃投了┃パス」を1つにつなぎ、主操作「ここに打つ」を右に離して同じ操作列に維持。
- 着手はどの盤・どのモードでも「仮置き→ここに打つ」の2タップで、1タップで打つ設定は置かない（決定。理由は原則 §2.2）。

### 2.6 採点操作

- 同じ操作列を「対局を再開／この計算に同意／…」（先へ進む操作を右）へ切り替える。
- 「対局を再開」では、押した側の相手から打つ（日本囲碁規約 第九条）。対COMならCOM、友人対局なら相手が先に打つ。1台で2人が打つときと観戦中は、誰が押したか分からないので手番を変えない。

### 2.7 終局提案

- 碁盤下の分析ステータスから必要時だけインライン展開。
- 対COMではCOMのパスが終局の提案に当たり、パスした時点で同じ欄に「COMがパスしました／採点を始めますか？」（打ち続ける／採点へ進む）を開く。採点へ進むは自分のパスで、そのまま採点に入る。
- 人のパスにCOMが打ち返したときは何も出さない。

### 2.8 終局判定

- KataGoのOwnershipは参考。提案はプレイヤーが明示的に行う。

### 2.9 死石

- 自動推定した候補を盤上で修正し、採点確定前に確認する。

### 2.10 終局後の次の対局

- 操作列に「履歴／新規対戦／もう一局（主操作）」。
- 新規対戦はそのモードで新規対戦シートを開く。
- もう一局は終わった対局と同じ盤・ルール・置き石（対COMは同じCOMと自分の石の選び方、観戦なら観戦）ですぐ始める。
- 対友人のもう一局は相手に申し込み、二人とも押すと同じ相手・同じ設定・同じ石の色で始まる。押した側のボタンは「相手を待っています」で無効になる。

### 2.11 友人招待

- 対局中に招待URLをもう一度見るときは「新規対戦」シートを開く。

### 2.12 新規対戦シート

見出しの右に［履歴］［？］［✕］。履歴は対局の種類ではないので見出しに置き、アイコンを名前の左に置く。選ぶと金の枠になり、シートの中身が履歴の一覧に変わる。

上から順に：

1. 対局の種類（［対COM｜観戦｜対友人］［1台で打つ］）。
2. 「自分の石／COMのキャラ／盤／ルール／時間」の下線タブ。
   - 色を先頭に、対局ごとに変えやすい順。
   - 各タブの名前の下に今の値を出し、開かなくても何で始まるか分かるようにする。そのモードで使わない項目は「—」。
3. その下の1枠に選んだタブの選択肢。
   - 丸・名前・説明を1行に並べ、行の間を細い線で区切る。行のどこを押しても選べる。
   - 選択肢の下には、そのタブにだけ関わる設定を区切り線と小見出しで続ける：
     - ルールタブに「ルールの追加設定」（置き石・禁じ手・石を隠す）。
     - COMのキャラタブはキャラ一覧の直下にカスタムの強さと好みを枠なしで出し、観戦のときだけ「COMの打ち方」（黒白のCOM）を続ける。
     - 時間タブは「持ち時間と秒読み」と「観戦の速さ」の2つの小見出しを並べ、そのモードで使わないほうをグレーアウトする（観戦は持ち時間なしで速さだけ、対友人と自由はどちらも使わない。タブの値は観戦なら速さ、ほかは「10分+30秒」のような持ち時間）。
   - 開閉する「詳細設定」は置かない。タブごとの長さは中身に合わせ、シート全体をスクロールする。
4. ［今の対局を続ける］［新しい対局を始める］の1行。
   - 設定を見てから押せるよう選択肢の後に置き、どのモードでもシートの下端に固定して常に見せる。開始ボタンが主操作で右端。
   - 左のボタンは行き先を名前で示し、設定画面の「戻る」と読み違えないようにする：今の対局なら「今の対局を続ける」、終局した対局なら「盤に戻る」、ほかのモードの途中の対局なら「途中のCOM戦を続ける」「途中の1台対局を続ける」。どのモードでも同じ位置に出し、履歴ではこのボタンだけが下端に残る。
   - 表記はどのモードも「新しい対局を始める」で、対友人では押すと招待URLができる（その後は「招待リンクをコピー」）。
   - さかのぼりから開いたときだけ「ここから打つ」。
   - 履歴では対局の種類の下に「SGFファイルを読み込む」。

全体の決まり：

- カードで囲まない。
- モードを切り替えてもシートの高さと行は変えず、そのモードで使わない設定はグレーアウトする。

COMのキャラ：

- 同じ並びの8択（ひよこ／石橋／荒らし屋／喧嘩屋／大場好き／本気／名人／カスタム。強さの順。名人は強さ「最強」）で、各行の説明は強さと1文。
- 初期値はいちばん弱い「ひよこ」。
- 選択肢の下に、選んだCOMの強さと好みを「強さ「やさしい」・戦い方「攻め込む」…」の1行で出す。
- カスタムのときはその1行の代わりに、選択肢のすぐ下へ強さと3つの好み（戦い方・序盤・相手の手に）の行を枠なしで出す。

### 2.13 設定・履歴

- 独立した小さなシート。普段は盤面の場所を占有しない。

### 2.14 着手禁止点

- コウ＝丸に斜線、自殺手＝丸に×。同じ色・大きさ・濃さ。

### 2.15 待った

- 全モードで操作列左端の同じボタン（↺＋「待った」）。仮置き中だけ×（仮置きを戻す）に変わる。
- 1台＝直前の1手、対COM＝自分の直前の手まで、対友人＝相手が受け入れたら自分の直前の手まで。
- URLの申し出と返答は終局提案と同じ欄で行う。

### 2.16 さかのぼり

- ステータス行の◁を押すと1手戻る。さかのぼり中は手番の欄に「28手目を表示中」、◁▷で1手ずつ動く。
- 最新の手に着いても対局には戻らない（勝手に画面が変わらない）。
- 手番の上の空きに、スライダーと試し打ちの道具を並べる（メニューに隠さない）。
- 試し打ちにパスのボタンは置かない（パスして相手に続けて打たせたいなら「ここから打つ」で対局を始め、ふつうのパスを使う）。
- 1手ずつの移動は◁▷だけで、同じ働きのボタンを二重に置かない。
- 再生列の左端は強調枠の「対局に戻る」（試し打ち中は「元の棋譜に戻る」）で、押すと戻る。
- 盤をタップすると試し打ちになり、確定ボタンは「試しに打つ」（対局の「ここに打つ」と名前で区別する）。試し打ちは元の棋譜を変えない。
- 再生列の主操作は「ここから打つ」で、新規対戦シートそのものを見出し「28手目から打つ」で開く（専用シートは作らない）。
  - モードと自分の石（観戦を含む）は新規対戦と同じ場所で選び、盤とルールは元の対局の値でグレーアウト、対友人と履歴もグレーアウト。
  - 開始ボタンは「ここから打つ」で、表示中の局面から新しい棋譜として始める（元の対局はそのまま履歴に残る）。
  - 履歴の対局の最後の局面で未終局なら、また対局中の棋譜の最新の手なら、同じ場所が「続きを打つ」になり元の対局を再開する。

### 2.17 形勢グラフ

- さかのぼり中の手数のバー（手番の上の全幅のスライダー）を形勢グラフにする。行は増やさず、高さは行と同じ44px。
- 折れ線は各局面の地合いから出した黒の目数差（コミ込み）で、上が黒、下が白。
- Chess.comなどのチェスの形勢グラフと同じ二色で、線より下を黒の側（背景に溶けないよう濃い灰色）、上を白で塗り、広い色が優勢の側になる。
- 推定がまだない局面は線を切る（つながない）。
- 打った側の推定が大きく下がった手を3つまで橙の点で示す（9路は3目以上、盤が大きいほど基準を上げる）。「悪手」などの判定の名前は付けない。
- 今の手数は金色の縦線と、スライダーと同じ金色のつまみ（直径16px）で示し、つかんで動かせると分かるようにする。
- 左上に「0」、右上に「N手」を小さく出し、横軸が手数だと示す。
- グラフを押す・なぞるとその手数を表示し、点の近くを押すとその点の手に合う。rangeはキーボードと読み上げ用に透明で残す。
- 推定はさかのぼり中に裏で計算し、地合いの表示を切っていても計算する。
- 終局前の対局をさかのぼるときは、対局中に形勢が分かってしまうのでグラフを出さない。それと五目並べ・自由な盤ではふつうのスライダーに戻り、そのつまみも20pxと大きめにする。

### 2.18 自分の石

- 対COM・対友人とも「● 黒／ランダム／○ 白」を同じ並びで出す（1台では行ごとグレーアウト）。
- 観戦は色ではなく対局の種類の1つなので、ここには置かない。観戦ではこのタブはグレーアウトし、速さ（ゆっくり／ふつう／はやい）は「時間」タブで選ぶ。
- 対局中に変えてもすぐ効く。
- 初期値は対友人＝ランダム、対COM＝黒、観戦＝ふつう。

### 2.19 観戦（COM同士）

- COMが両方の色を一手ずつ間を置いて打つ。
- 操作列は「介入する」と「一時停止（再開）」の2つにする。盤をタップしても何も起きない。
- 「介入する」を押すとCOMは止まり、盤をタップするとその手番の石を仮置きできる。ふだんの対局と同じく別の点を打てば仮置きが動き、金の「ここに打つ」で確定するとその色を引き継いで、以後はふつうの対COMになる。
- 「×」で介入をやめると、少し間を置いてから観戦を続ける。その間は手番の欄に「観戦に戻ります…」と出す。
- 「採点を始める」はCOMの考慮中でも押せ、押すとCOMは止まって採点するかを聞く（「打ち続ける」で再開）。
- COMがパスすると終局目安の欄に「黒がパス。次もパスなら採点へ」と出し、観戦者に打つよう求めない。
- ◁でさかのぼると対局は一時停止になり、形勢グラフが出る（観戦者は対局者ではないので、対局中でも見せてよい）。「対局に戻る」の後は一時停止のままで、「再開」で続ける。
- 観戦中は盤の拡大を保つ。
- 黒と白のCOMはキャラを別々に持つ。
  - 観戦の「COMのキャラ」タブには、キャラの一覧の代わりに最初から「● 黒のCOM」「○ 白のCOM」の枠を1つずつ出す。
  - 枠の中はキャラの選択（カスタムを含む8択のプルダウン）で、カスタムのときだけ強さと3つの好みの行を選択肢ボタンで並べる（説明文や目盛りは付けない）。
  - 片方の値を隠す切り替えは置かない。

### 2.20 自由に置く

- 新規対戦のルール「自由」。いつも表示し、使えない対COMではグレーアウトする（1台で打つ・対友人で使える）。
- 交点をタップするとその点を金の輪で示し（仮置き）、「ここに打つ」の位置が左右2つのボタンに分かれる。
  - 空いた交点は「● 黒｜○ 白」、石は「取り除く｜○ 白にする（● 黒にする）」。押すとすぐ盤に反映し、待ったで戻せる。
  - 点を選ぶ前は2つとも無効。×で選択を外す。2つは「ここに打つ」を分けたものなので、融合した主操作（金）にする（§3.6 の唯一の例外）。
- 操作列は「待った（×）／左右のボタン」。
- 手番はなく、対友人ではどちらもいつでも両方の色を置ける。同時に置いて食い違ったら招待した側の盤に合わせる。
- 石は取れず、着手禁止点・パス・投了・採点はない。地合いの色は通常どおり表示する。
- SGFと共有リンクはその局面の置き石（AB/AW、RU[Free]）で書き、着手のない置き石だけのSGFは自由な盤として開く。

### 2.21 ヘルプ

- 説明文は見出し右上の「?」から開くヘルプシートに集約する。
- 各画面には小さな「?」（`.help-button`、`data-help`で話題を指定）を置き、押すとその話題だけを「?」のそばの小さなポップアップで表示する（本文はヘルプシートの項目を複製し、二重に書かない）。ほかの場所をタップするかEscapeで閉じる。
- 設定や操作欄には長い説明文を置かない。
- 先頭の「初心者の方へ」から、ルールと今の局面について好きなチャットAIに聞く質問文をコピーできる（P2Pの部屋URLは含めない）。

## 3. ボタンの規則

### 3.1 種類（4種類のみ）

| 種類 | クラス | 用途 | 例 |
| --- | --- | --- | --- |
| 主操作 | `.primary`（金） | その列で最もよく使い、取り消せる前進操作。1列に1つまで | ここに打つ、この計算に同意、もう一局、採点へ進む（1台・対COM） |
| 通常 | `.secondary`（素の `<button>` も同じ見た目） | それ以外のすべて | パス、待った、対局を再開、メニュー内の各項目、設定シートの各操作 |
| 強調枠 | `.accent-outline`（金の枠と文字） | 今の画面から離れる、または説明を得る補助操作 | 対局に戻る／元の棋譜に戻る、チャットAIに質問、SGFファイルを読み込む |
| 確認待ち | `.danger-armed` | 取り消せない操作が2回目のタップを待っている状態 | 投了？ |

- 色は `:root` の `--btn-*`・`--accent-*`・`--danger-*` だけから取り、ボタン個別の色指定はしない。
- 対局画面（ヘッダーと盤の下）では、まとまりをパネルやカードで囲まず、余白で分ける。ただしボタンの縁は残す（理由は原則 §2.3）。
  - 盤の下のボタンは控えめな灰色の縁（`--btn-edge:#5a6273`）、融合したボタンは外側も境目も同じ色の線にする。
  - ヘッダーのアイコンは縁なしで、「新規対戦」だけ白い縁を付ける。
  - 金の縁（主操作・強調枠）は残す。
  - シートの中はこれまでどおり。
- 例外は見出し・シートの透明なアイコンボタン（`.icon-button`）、局所ヘルプの「?」（`.help-button`）の2つだけ。ステータス行の◁▷も `.icon-button`（枠なし、無効時は薄く）で描く。「?」は行の高さを変えないよう小さく描き、`::after`でタップ領域を広げる。
- 相手との交渉（URL対戦の終局提案・待ったへの返答）では、どちらの選択肢も主操作にしない。
- ポップオーバーの中では主操作を使わない。
- 自由な盤では「ここに打つ」の位置の「● 黒┃○ 白」を2つとも主操作にする（1列に1つの例外。融合して1つの部品に見せる）。

### 3.2 寸法

- 盤下の操作列・採点列・再生列は同じ高さ `--action-h`（55px、幅700px以下は54px）。状態が変わっても行の高さは変わらない。
- それ以外のボタンは `--control-h`（44px）以上。
- 角丸は `--radius`（13px）。ポップオーバー内の小さなボタンだけ `--radius-sm`（10px）。

### 3.3 文言とアイコン

- 同じ操作は、どこでも同じ名前と同じアイコンにする。
  - 仮置きを戻す：×アイコン（aria-label「仮置きを戻す」）。対局中でも棋譜再生中でも同じ。
  - 履歴を開く：行き先の名前は「履歴」。開くボタンは、終局後の操作列でも新規対戦シートの見出しでも「履歴」。
- **操作は動詞、行き先と状態は名詞**にする（理由は原則 §2.4）。
  - 押すと何かが起きるボタンは、動詞で終える（「SGFを保存」「採点を始める」「ここに打つ」「招待リンクをコピー」）。
  - 押すとその画面やシートを開くボタンは、行き先の名詞でよい（「履歴」「新規対戦」「設定」）。
  - 囲碁の行為として名前が定着している操作は、その名詞のまま使う（「パス」「投了」「待った」「もう一局」）。
  - 状態の表示は名詞か「〜中」で書く（「採点中」「28手目を表示中」）。
- 語は §8 の用語集にそろえる。
- シートの閉じる、前後移動、メニュー、ヘルプ項目の開閉はSVGアイコンで描き、文字の記号（× ‹ › ≪ ≫ ••• ▶）は使わない。
- アイコンは 24×24 の viewBox で描き、大きさは2つだけにする：22px（ヘッダー、閉じる、前後移動、モード、盤の大きさ、待った）と 18px（文字の横の「?」、コピー、初期状態に戻す、開閉の印）。
- 線の太さも2つだけにする：ふつうは `--stroke-icon`（2）、碁盤の線を描く盤の大きさのアイコンだけ `--stroke-grid`（1）。太さは CSS でトークンから指定し、svg の `stroke-width` 属性には書かない。

### 3.4 確認の手順

| 操作の性質 | 確認 | 例 |
| --- | --- | --- |
| 取り消せる | 1タップ | パス（待ったで戻せる）、「新規対戦」→「新しい対局を始める」（直前の対局は履歴に残る） |
| 取り消せない、盤下の操作列にある | その場で2回押す | 投了 |
| 取り消せない、モード選択やシートから盤面を離れる | その場で2回押す。加えて直下に何が起きるかを一文で示す | 友人との対局から離れる |

- 2回押しの1回目では、必ずボタンそのものを変える。`.danger-armed` の色にし、ラベルの末尾を「？」にする（例：投了→投了？、友人との対局から離れるときの新しい対局を始める→新しい対局を始める？）。色だけ・周囲の文だけの変化にはしない。
- ブラウザの確認ダイアログ（`confirm()`・`alert()`）は使わない（理由は原則 §2.5）。
- 確認待ちは、そのボタン以外を押すかシートを閉じると解除する。

### 3.5 メッセージの書き方

エラーや注意の文言は、状態の説明ではなく**利用者が次にすること**を先に書く。

- 「次にすること。理由。」の順にする。理由は行動に納得するのに要る分だけ短く添え、明らかなら省く。
  - よい例：「別の交点を選んでください。コウで打てません。」「今の招待URLをそのまま使ってください。招待は作り直せませんでした。」
  - 避ける例：「その交点は禁止です。コウだからです。」「局面が一致しません」
- その場でできない操作は、文言で断らずにボタンを無効化（グレーアウト）する。押せる操作には失敗の説明を出さなくて済むようにする。
- 利用者の言葉で書く。システムの用語（同期、接続、データ、不正、初期化、サーバーの応答など）は使わない。「本人確認」のように仕組みと違う言い方もしない（Turnstileは「ロボットでないことの確認」）。
- 壊れた棋譜・SGF・URLは、壊れ方を区別せず一つに扱い、その場面でできること（別のファイルを選ぶ、URLを送り直してもらう等）を出す。対応していない形式は、選ぶべきファイルの条件を書く（「512KB以下のSGFファイルを選んでください」）。
- 画面に出すのは `public/texts.mjs` の文言だけ。ブラウザ・サーバー・プログラム内部のエラー文はそのまま見せず、場面ごとの文言に置き換える（`UserError` と `messageFor`）。開発者向けのログや例外は英語でコードの横に書く。
- 進行中の表示（「〜中…」「相手を待っています」）は、することが「待つ」だけなので状態のままでよい。
- 表示枠に収める（幅360pxで確認）。
  - 手番の横の接続状態：短い状態だけ（「つながりません」）。することはヘッダー下のお知らせに出す。
  - 禁止手の表示：2行以内（盤下の欄の高さは変えない）。
  - お知らせ：2行以内。

### 3.6 関連するボタンの融合

関連するひとまとまりのボタンは、区切り線でつないだ1つの部品（`.fused`）にする。無関係なボタンとは今までどおり隙間をあける。

```
[1][2][3][A]  →  [1┃2┃3]  [A]
```

- **融合するもの**
  - 1つの問いへの選択肢（ラジオ）：新規対戦の対局の種類・盤・ルール・自分の石、設定の濃さ（V字／U字）。
  - 同じ場面で並ぶ同格の操作：操作列の「待った┃投了┃パス」、採点列の「対局を再開┃死石判定に戻る」。
  - 縦に並ぶ同じ種類の操作：共有シートの棋譜の3つ、ヘルプ「初心者の方へ」の質問コピー2つ（`.fused-column`）。
- **融合しないもの**
  - 主操作（`.primary`）。常に独立させ、隣と隙間をあける（ここに打つ、この計算に同意、もう一局、開始ボタン）。 例外は自由な盤の「● 黒┃○ 白」で、ここに打つを2つに分けた主操作どうしを融合する。
  - 強調枠（`.accent-outline`）とメニュー（•••）。今の画面から離れる操作なので、まとまりの外に置く（再生列の「戻る」）。
  - 見本の絵で選ぶカード（碁盤の見た目、地合いの配色、共有画像の種類）。絵どうしを比べやすいよう1枚ずつ枠で囲む。
- **描き方**
  - 外枠は1本、角丸はまとまりの両端だけ。区切り線は1px（`--btn-edge`、シートの選択肢は `#505766`）。
  - 選んでいる選択肢は、今までどおり金の文字と背景に、内側の金の線を加える。
  - 無効なボタンはボタン全体ではなく文字だけを薄くし、区切り線の濃さを揃える。
  - まとまりの一部が非表示になっても線は余らない。全部が非表示ならまとまりごと消える。
  - 高さとタップ領域は §3.2 のまま（44px以上、盤下の列は `--action-h`）。融合で隙間がなくなる分、320px幅で隣のボタンが広くなる。
- 1つのまとまりは5つまで（iPhoneの目安）。それを超えるなら選び方そのものを見直す。
- 取り消せない操作（投了）がまとまりに入っても、§3.4 の2回押しで誤タップを防ぐ。

## 4. 状態別の画面規則

| 状態 | 目立たせるもの | 抑える／非表示にするもの |
| --- | --- | --- |
| 自分の手番 | 手番表示、碁盤、着手操作、合法・禁止点 | COM・通信の詳しい説明 |
| 仮置き中 | 仮置き石、確定・戻す操作 | 不要な操作の有効化 |
| COM考え中 | 考え中の表示、盤面 | 人間の着手確定操作 |
| 観戦中 | 盤面とグラデーション、手番、一時停止、「介入する」の後の盤タップ（×・ここに打つ）、さかのぼりと形勢グラフ | 着手・待った・パス・投了 |
| 相手待ち／切断 | 接続状況、再接続の見通し | 成立しない対局操作 |
| 終局を提案・受信 | 終局ステータス、必要な同意・続行操作 | ポップアップ・独立した固定バー |
| 死石解析中 | 解析中表示、盤上の死石修正、対局再開 | **採点確定ボタンを有効化しない** |
| 採点確認中 | 石の仮指定、目数、採点の再開／同意 | 通常の着手操作 |
| さかのぼり中・試し打ち中 | 表示中の手数（「28手目を表示中」「試し打ち 29手目」）、◁▷、手番の上のスライダーと道具、再生列の「対局に戻る」 | 終局バー・対局の着手操作 |
| 対局終了 | 勝敗・目数（投了では投了勝敗）、棋譜 | 無効な着手操作 |

## 5. 最小寸法（決定）

根拠は原則 §2.6。未決の検討事項は原則 §3。

- **縦画面 320×568px を必須**とする。この大きさで、碁盤・ステータス・操作列が縦スクロールなしで1画面に収まり、文字が切れず、ボタンが押せること。これより小さい画面は対象外。
- **押せるものは 44×44px 以上**。見た目を小さく描くもの（「?」、◁▷、スライダーのつまみ）は `::after` などでタップ領域を広げ、見た目と押せる範囲を分ける。
  - 例外：盤の交点。仮置き→「ここに打つ」の2段で誤タップを防ぐ（§2.5「着手操作」）。
- **文字は 11px 以上**。11px は凡例やバッジなどの補足だけに使い、手数・手番・ルール表記・得点の内訳など対局中に読む情報は 12px 以上にする（§7.1）。
- **有効な文字の対比は WCAG の 4.5:1 以上**（大きい文字は 3:1）。無効の表示は対象外。

## 6. レビュー時の確認環境（暫定）

- 320×568、375×667、390×844、430×932相当のスマートフォン**縦画面**を優先。
- 768×1024のタブレット、一般的なデスクトップは二次対応。
- **スマートフォン横画面は合否の対象外**とする。
- 3モード（1台・対友人・対COM。対COMは観戦を含む）× 主要状態（通常、仮置き、待機、終局提案、採点、終了、失敗）をテスト。
- 機能テストだけでなく、実機の画面外への押し出し、同意・戻るの誤操作、通信復帰時の状態を確認する。

## 7. 型（トークン）

見た目の数値は `public/style.css` の `:root` にトークンとして置き、各部品はトークンだけから取る（直書きの値を足さない）。値の正は `:root` で、この節は段の数と使い分けを決める。段を増やすときは、先にこの節を直す。

### 7.1 文字

| トークン | 大きさ | 使い道 |
| --- | --- | --- |
| `--font-caption` | 11px | 最小。注記、凡例、バッジなどの補足だけ。対局中に読む情報には使わない |
| `--font-small` | 12px | 手数、「打つ番です」、ルール表記、採点の内訳、小さいボタン |
| `--font-body` | 14px | 本文、設定の項目名、操作列のラベルすべて |
| `--font-title` | 17px | 手番、シートの見出し、合計点 |
| `--font-display` | 22px | ロゴ |

- 5段だけを使う。同じ列に並ぶボタンは同じ段にそろえる（操作列の「待った┃投了┃パス」と「ここに打つ」）。
- 例外は2つ：待ったのアイコンの下の字（12px）と、320px での「採点を始める」（11px）。
- 幅が狭いときに文字を縮めて収めるのは、この例外だけにする。ほかは文言を短くする（§3.5）。
- ロゴだけは別の書体（明朝系）でよい。

### 7.2 色

- ルールに16進の色を直接書かない。色はパレットのトークン（「系統-OKLabの明度」、例：`--slate-71`、透明度つきは `--gold-85-a40`）から取る。系統は black／white／gray／slate／sand／gold／ember／green。OKLab で 0.02 未満しか違わない色は1つにまとめる。
- 部品は役割のトークンを使う：文字は本文・控えめ（`--muted`）・金（`--gold`・`--accent-text`）、面は `--surface`・`--btn-bg`、線は `--edge`・`--btn-edge`。役割のトークンの中身がパレットを参照する。
- ボタンの色は §3.1 のとおり `--btn-*`・`--accent-*`・`--danger-*` だけから取る。
- 碁盤と地合いの色は碁盤の見た目ごとの設定（`board-theme.mjs`）が持ち、画面の枠のトークンとは分ける。
- 画面の枠はダークだけ（`color-scheme: dark`。理由は原則 §2.1）。

### 7.3 角丸

| トークン | 値 | 使い道 |
| --- | --- | --- |
| `--radius` | 13px | ボタン、タイル、盤の枠 |
| `--radius-sm` | 10px | 選択肢、通知、ポップオーバー内の小さなボタン |
| `--radius-sheet` | 20px | シート（スマホでもPCでも同じ） |
| `--radius-inset` | 8px | 盤面、色見本、入力欄 |
| `--radius-inner` | 6px | 小さい札、縮小図 |
| `--radius-xs` | 4px | グラフ |
| `--radius-hair` | 2px | 細い帯 |
| `--radius-pill`／`--radius-round` | 999px／50% | 丸い札、丸 |

- 部品が大きいほど大きい角丸にする。表にない値を使わない。

### 7.4 余白と高さ

- 画面の左右の余白は1つの値にし、ロゴ・碁盤・ステータス・操作列の左端と右端をそろえる（トークン化は未了）。
- 高さは `--control-h`（44px）と `--action-h`（55px、幅700px以下は54px）。

### 7.5 アイコン

- SVG（24×24 の viewBox）で描き、大きさと線の太さの段は §3.3 のとおり。
- アイコンの絵は押せる範囲（44px）の中央に置き、絵の端ではなく押せる範囲の端を余白にそろえる。
- 形勢グラフの線（`--stroke-hair` 1・`--stroke-mark` 2・`--stroke-halo` 3px）と濃さの図（`--stroke-shape` 2.4）はアイコンではないので別に持つ。

## 8. 用語集

画面の文言はこの表の語にそろえる。表にない語を新しく使うときは、先にここへ足す。コード・コメント・開発者向けの文書は対象外。

| 使う語 | 意味 | 使わない語 |
| --- | --- | --- |
| COM | アプリの中の対戦相手（キャラ・強さを持つ）。「対COM」「COMの番です」「COMが考え中です」「COMのキャラ」 | AI（対戦相手の意味で）、KataGo、エンジン |
| チャットAI | ChatGPT や Claude など、利用者が自分で使う外部のAI。「チャットAIに質問」「チャットAI向けにコピー」 | AI（単独で） |
| 対COM／観戦／対友人／1台で打つ | 対局の種類。履歴の記録名は「COMと対戦」「友人と対戦」「1台で打つ」 | AI対局、URL対戦、ローカル |
| 履歴 | 保存した対局の一覧（行き先の名前）。終局後の操作列のボタンも、新規対戦シートの見出しのボタンも、ヘルプの項目も「履歴」 | 対戦履歴、棋譜一覧 |
| 地合い | 盤上の色で示す、どちらの地になりそうかの推定 | KataGoによる推定、影響モデル、Ownership |
| 形勢 | 地合いから出した目数差。「形勢グラフ」 | 評価値、勝率 |
| 決着手順 | 採点の前に、勝敗が変わらないところまでCOMが残りを打ち進める手順。画面では「ダメを詰め中」。盤には打ち進めない | 決着中、プレイアウト |
| 仮置き／ここに打つ | 盤をタップして石を仮に置くこと／それを確定する主操作 | 選択、確定 |
| 試し打ち／試しに打つ | さかのぼり中に、元の棋譜を変えずに別の手を打つこと／その確定 | 変化、バリエーション |
| 対局に戻る | さかのぼりから今の対局の画面へ戻る。再生列の強調枠のボタン | 現在の対局に戻る |
| 今の対局を続ける | 新規対戦シートを閉じて今の対局へ戻る。開始ボタンの左に並べ、行き先を名前で示す（終局した対局なら「盤に戻る」） | 戻る、対局に戻る |
| 入門／やさしい／ふつう／つよい／最強 | COMの強さ。キャラ名と並べて「ひよこ 入門」のように出す。段級位とは対応しない | はじめて（相手が初めてと読める） |
| 読み | 最強のCOMが形勢の悪いときだけ数手先を調べること。「3手読み」 | 探索、サーチ |

- 仕組みの名前（KataGo、Web KaTrain）は、ヘルプの「このアプリについて」のクレジットとライセンスだけに書く。
- 検索エンジン向けの説明（`page.description`）と、AIが読む文書（`llms.txt`・`ai.md`）は、探す人の言葉に合わせて「AI」を使ってよい。
